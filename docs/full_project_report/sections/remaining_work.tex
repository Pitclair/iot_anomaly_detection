\section{Remaining Work Before Final Thesis Claims}

\subsection{Start writing from the implemented method}

The methodology, architecture, numerical contracts, input safeguards, recovery
mechanism, and simulation design can be written now. The system has enough
completed implementation to support those chapters. The next phase should
freeze the reported software and complete its evidence, rather than adding
every feature mentioned in an older plan.

Record one reference revision, chosen datasets, device selectors, counting
policy, window duration, calibration rule, policy variants, metrics, and
artifact paths. Keep static, legacy, and conservative results identifiable.
The retained detector uses four input counts, joint composition/volume/ARP
scoring, and fixed update references. Further feature extensions require their
own justified comparison.

\subsection{Freeze an independent evaluation protocol}

The ordinary \path{score_windows()}, \path{adapt_windows()}, and
\path{evaluate_scores()} select development data. The detection experiment
runner can also replay the declared later partitions through the same
one-window detector, with isolated comparison reports. Those labels have been
inspected during candidate assessment, so another replay cannot be presented
as an untouched final test.

Freeze the detector revision, learning settings, evaluation command, and data
selection before an independent test. Keep fit/calibration data separate and
retain events, update attempts, and metrics together. An explicit ordinary
CLI partition option could simplify this workflow, but it would not restore
independence to labels already examined.

\subsection{Refresh the definitive comparison reports}

All three research starting pairs and all experiment configurations validate.
The central detection comparison records cover static, conservative, and legacy
operation at the shared 144-window update schedule. The six schedule-specific
conservative directories remain a separate incomplete bundle. Historical legacy
reports predate the FPR output field, so their table values are calculated from
stored confusion counts; current static and detection records carry their own
metrics.

After the protocol is frozen, complete only the schedule comparisons required
by the research questions, using isolated paths and the same starting pair.
Retain event files, accepted/rejected attempts,
alpha and threshold movement, metrics, environment, configuration, and
revision together. If every conservative candidate is rejected, report that
negative result. Do not loosen guards solely to manufacture a promotion.

\subsection{Handle chronology and final-data reuse honestly}

The current validator enforces chronology of capture identifiers; the stream
enforces actual window order within its own run. Complete source-timestamp
validation across captures remains on the temporal branch. Known D-Link
October 8/9 overlap must be resolved or the affected numerical-only result
clearly bounded before a new scientific fit relies on it.
The temporal implementation is available for reuse if that work is selected.

Final-test access must be assessed across the whole project, not only one
branch. Both the earlier feature experiments and the retained detector audits
have inspected later labels. They cannot be called wholly unseen after
candidate assessment. Freeze what can validly be tested on the remaining
data, disclose prior exposure, and select a new external test if an independent
claim about a refined detector requires one.

\subsection{Optional research and future deployment}

Merging rolling folds, validating additional packet-level features, comparing several
window durations, adding block confidence intervals, implementing empirical
forecasting, or validating a physical gateway are separate scope decisions.
The minimum supplied-window simulation does not require all of them.
Older reports' broader improvement lists should not become new mandatory
software requirements merely because they exist in the repository.

For the thesis, complete the evidence required by the agreed research
questions, generate figures and tables from that frozen bundle, write the
results and discussion, and validate the final PDF/A and metadata.
The completed local simulation should remain labelled as simulation.
