\section{Testing, Reproducibility, and Operational Errors}

\subsection{Fresh verification for this report}

On the reference implementation plus the thesis workspace, the full suite was
run with every marker group enabled and the production edge image selected.
\textbf{All 560 tests passed in 39.56 seconds.} This includes the ten tests
normally excluded by the default slow/PCAP/benchmark selection and the two
opt-in Docker checks. A normal run without the image variable skips those
Docker checks; it must not be described as container verification.

Tests include small unit inputs, numerical comparisons, real CLI subprocesses,
temporary state directories, synthetic packet/PCAP fixtures, and isolated
containers. Parameterisation contributes multiple cases to the count.
The number of passing tests is not a measure of attack coverage or scientific
generalisability.

\subsection{The boundaries that are exercised}

Configuration and schema tests reject unknown settings, incompatible artefacts,
invalid counts, wrong identities, malformed timestamps, and unusable buffers.
Processing tests check Ethernet/ARP selection, exclusive SSDP classification,
UTC boundaries, silence, missing coverage, and exact stored window shape.
Capture tests distinguish structural warnings from fatal truncation and retain
diagnostic evidence for failures.

Numerical tests compare SciPy, native LM, and high-precision reference cases;
they cover sparse and zero counts, large concentrations, matrix semantics,
repeated calls, and precision failures. Modelling/calibration/scoring tests
check the common statistical convention and threshold fingerprint.
Evaluation tests check exact label alignment, duplicates, confusion counts,
and FPR for hand-counted, no-benign-label, and zero-false-positive cases.

Adaptation tests verify score-before-learn ordering, bounded buffers, admission
rejection, concentration/proportion/threshold limits, convergence and
likelihood rejection, permitted promotions, and preservation of legacy
behaviour. Twelve mode/policy/score combinations compare real command
dispatch with batch output and final detector state.

State tests exercise immutable versions, pointer activation, restoration,
locking, rollback, retained history, abandoned-file cleanup, and failures at
different save stages. ENOSPC is injected as a storage exception rather than
filling a physical disk. Signal tests request shutdown while idle and during
atomic activation. These are controlled fault checks, not physical power-loss
or filesystem-certification experiments.

Container tests use the built image without downloading a compiler or test
extra. The fixture is replayed through the actual launcher, and the service
is checked for failure restart, accepted-state recovery, bounded output,
resource limits, and an explicit stop that remains stopped.

\subsection{Stable command errors}

Expected domain failures are converted to a concise message and a stable exit
code at the CLI boundary. An optional JSON error format makes the failure
machine-readable. Successful output is not emitted for a failed operation.

An adaptive candidate rejection is usually an audit outcome while the detector
continues on the valid pair. An initial training failure is a command failure.
The committed-state exception is deliberately different from both: after the
pointer changes, the process stops instead of continuing from an uncertain view
of state.

\subsection{Public smoke evidence}

\path{tests/data/smoke/synthetic_packet_counts.json} is a payload-free CC0
fixture with no real network identifiers. It produces exactly three known
windows: $(2,1,0,0)$, a missing interval, and $(0,0,1,2)$.
The smoke module checks aggregation, deterministic toy parameters, anomaly
injection, metrics, fixture hashing, and reproducibility across subprocesses.
Its own record labels it an infrastructure experiment with no scientific claim.
It is not a substitute for the verified DM estimator or labelled evaluation.

The separate edge fixture contains five already aggregated windows and emits
four events. It checks the stream interface and resource path. Neither fixture
estimates detection accuracy on real attack traffic.

\subsection{Seeds and provenance}

Four seed fields are declared: simulation, model fitting, bootstrap, and
randomised algorithms. The named-generator helper currently exposes independent
simulation and model-fitting generators without modifying NumPy's global RNG.
Production Minka initialisation is deterministic from counts; the presence of a
model-fitting seed does not imply random fitting or multiple sampled runs.
The forecast scaffold has its own fixed local seed. No capture-block confidence
interval is claimed merely because a bootstrap seed exists.

Experiment-manifest schemas can record a code commit, configuration hash,
dataset hash, command, and seed. Not every older report automatically contains
every manifest field. Retained configurations, fingerprints, source revisions,
and environment records must therefore be assembled into one final evidence
bundle rather than inferred from filenames.

\subsection{Limits of this verification}

All configured starting model/threshold pairs validate, and processed-window
totals were checked directly. Historical and research-branch reports were read
from their recorded revisions. No production code, final-test policy, or
research branch was changed for the report. Full raw-data preprocessing,
all historical fitting runs, long resource trials, physical hardware, and final
PDF/A certification were not repeated.
